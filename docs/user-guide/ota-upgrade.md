# OTA 升级使用说明

> **适用角色**: 租户管理员、运维（需 `ota:read` / `ota:upload` / `ota:deploy` 权限）

---

## 1. 固件管理

1. 进入「OTA 与固件」→「固件库」。
2. 「上传固件」：选择产品、填写版本、上传文件；上传成功后自动带出文件地址与 MD5。
3. 如固件有 SHA-256 摘要与签名，在创建/编辑时填入。
4. 「校验」→「发布」，仅已发布固件可用于升级任务。

## 2. 创建设备版本记录（可选）

在「设备版本」页可登记设备当前固件版本、批量绑定固件，用于升级前后对照。

## 3. 创建升级任务

1. 进入「升级任务」→「新建任务」。
2. 填写：
   - 任务名称、描述；
   - 所属产品；
   - 目标固件（仅展示已发布固件）；
   - 任务类型：全量 / 灰度；
   - 源版本（可选，按设备当前版本筛选）；
   - 指定设备（可选，多选；留空则按产品与源版本筛选）；
   - 灰度比例（灰度类型时必填，取前 N% 设备）。
3. 创建后平台立即展开设备、下发升级指令，任务状态为「执行中」。

## 4. 查看进度

- 任务列表「进度」列展示成功/失败/总数与百分比。
- 点击「详情」查看逐设备状态：待下载 / 下载中 / 升级中 / 成功 / 失败 / 已取消，以及进度、错误与更新时间。
- 设备上报 `device.ota.progress` 后自动更新；全部设备结束任务变为「已完成」或「失败」。

## 5. 取消任务

执行中任务可「取消」，平台停止后续下发，未终结设备标记为已取消；已下发设备的升级需设备侧处理。

## 6. 设备侧要求

- 订阅 `/sys/{productKey}/{deviceName}/thing/ota/upgrade` 接收升级指令。
- 指令 payload 包含：`taskId`、`firmwareId`、`version`、`url`、`fileSize`、`md5`、`sha256`、`signature`。
- 上报 `device.ota.progress`，建议携带 `taskId`、`progress`（0-100）、`status`、`errorMessage`。

## 7. 注意事项

- 仅「已发布」固件可创建任务。
- 灰度当前按设备 ID 顺序取前 N%，不是分批推进。
- 固件携带签名时必须由运维配置验签公钥，否则校验失败。
- 进度未携带 `taskId` 时按设备最近未终结任务匹配，多任务并行请显式携带。
