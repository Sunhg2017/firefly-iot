# 下行消息持久化投递（Outbox）使用说明

## 1. 适用角色

- 平台运维、设备接入开发：理解下行指令的持久化与重试语义。

## 2. 行为说明

1. 云端下发指令（属性设置、服务调用、OTA、远程配置、批量操作等）时，先持久化到 `downlink_outbox`，再发布 Kafka。
2. 设备在线时 connector 立即投递并回执，outbox 置 DELIVERED。
3. 设备离线时，指令保留为 PENDING，重试任务按 30s 起指数退避重发；达到最大次数（默认 5 次）后置 FAILED。

## 3. 注意事项与限制

1. 投递为「至少一次」，设备需按 `message_id` 幂等处理重复指令。
2. FAILED 记录不会自动清除，需运维关注并人工处理。
