# 消息与数据可靠性使用说明

> **适用角色**: 运维、租户管理员

---

## 1. 下行补发

- 设备离线时平台下发的指令不会丢失，会进入设备待投递队列（每设备最多 100 条，保留 24 小时）。
- 设备重新连接后自动补发；补发失败会保留剩余消息等待下次重连。
- 可通过日志 `Flushed pending downlink` 确认补发数量。

## 2. 设备影子

- 平台下发的期望值（desired）已持久化到数据库，Redis 淘汰或重启后不会丢失，页面读取时会自动回源。
- 设备上报状态（reported）保存在 Redis，属于实时状态，Redis 重启后需设备重新上报。

## 3. 告警

- 同一规则、同一设备在告警未关闭前只会产生一条进行中告警，避免并发/重放导致重复。
- 通知渠道失败会自动重试（默认 3 次），仍失败可在通知记录中查看错误。

## 4. 遥测与日志

- 遥测原始 payload 按消息只存一份，属性行不再重复存储整包 payload。
- 遥测、设备日志、设备事件、操作日志、审计日志均按保留天数定时清理，保留天数由运维配置。

## 5. 注意事项

- 待投递队列依赖 Redis，Redis 数据丢失会丢失未补发指令。
- 历史 `device_telemetry.raw_payload` 数据保留但不再新增，可按保留策略自然过期。
- 告警迁移会关闭历史重复的进行中记录，升级前请知悉。
