# 设备模拟器交互与批量压测重设计

> 模块: `firefly-simulator`
> 日期: 2026-11-15
> 状态: Done
> 关联: [设备模拟器运维说明](../operations/device-simulator-redesign.md)、[设备模拟器使用说明](../user-guide/device-simulator-redesign-guide.md)

## 1. 背景

原模拟器是一个固定 `1760×960` 画布缩放的单页工作台：左侧设备卡片、中间单设备控制、右侧工具与日志。存在明显问题：

- 所有功能挤在一屏，屏幕较小时整体缩放导致文字和控件过小，信息层级不清。
- 设备以卡片列表展示，没有多选、分页和表格列，设备多时无法快速筛选、对比和批量操作。
- “批量创建设备”只填名称和协议，不带产品、密钥和接入地址，创建出的设备通常无法连接。
- 压测是弹窗内的简单循环：只支持 HTTP/MQTT/CoAP，最多 100 台，没有并发模型、爬坡、超时、暂停/继续和协议分布。
- 批量连接串行执行，几百台设备时耗时很长，且没有进度。
- 压测数据、历史结果和错误原因展示有限，无法定位瓶颈。

## 2. 目标

- 信息架构从“单屏工作台”改为“按任务分页”：设备管理、压测中心、运行日志、工具。
- 设备管理以表格为主，支持搜索、协议/状态筛选、多选、分页、批量连接/断开/删除、批量创建。
- 压测中心成为独立工作区：选设备 → 配负载 → 运行 → 实时观测 → 导出报告。
- 压测支持固定请求数与持续时长两种模型，支持并发 Worker、发送间隔、爬坡、超时、暂停/继续/停止。
- 覆盖 HTTP / MQTT / CoAP / WebSocket / TCP / UDP / LoRaWAN / SNMP / Modbus；视频/GB28181 明确不参与批量压测。
- 批量创建支持产品选择、命名规则、动态注册、接入地址预填和创建后自动连接。
- 取消固定画布缩放，使用浏览器/桌面窗口的自然流式布局。

## 3. 信息架构

| 页面 | 职责 |
| --- | --- |
| 设备管理 | 环境与登录、设备表格、单设备新建/编辑、批量创建、批量连接/断开/删除、导入/导出、打开设备详情 |
| 压测中心 | 选择目标设备、负载模型、发送内容、运行控制、实时指标、协议分布、错误 Top、历史与报告导出 |
| 运行日志 | 全量日志、按当前设备过滤、自动滚动、导出/清空 |
| 工具 | 场景编排、数据模板、压测建议、快捷键 |

设备详情不再占用主界面固定一列，改为从表格打开右侧 Drawer，复用原有单设备控制面板（HTTP/MQTT/CoAP/Video/SNMP/Modbus/WS/TCP/UDP/LoRaWAN 等专属面板）。

## 4. 设备管理设计

### 4.1 表格

列：设备名、协议、状态、接入标识、发送/错误、自动上报、操作。

- 接入标识按协议展示业务键（ProductKey/DeviceName、SNMP/Modbus 目标、WebSocket/TCP/UDP 地址、LoRa DevEUI），不突出内部主键。
- 操作列：连接/断开、详情、编辑、复制、删除（删除有二次确认）。
- 支持按协议、状态、关键字筛选；分页可选 20/50/100/200。
- 勾选跨分页保留；批量操作按“全部已选设备”执行，而不是只对当前页生效。

### 4.2 批量创建

Drawer 表单：

- 通用：协议、数量（1-2000）、名称前缀、起始序号、位数、名称预览。
- 产品：登录后可按协议加载平台产品，自动带出 ProductKey 与认证方式；也可手工填写。
- 认证：
  - HTTP/MQTT 支持“动态注册（ProductSecret）”，每台设备连接时换取 DeviceSecret。
  - 其他协议使用统一 DeviceSecret 或创建后逐台补充。
- 接入地址：HTTP/CoAP/MQTT/WS/TCP/UDP/LoRaWAN/SNMP/Modbus 按环境默认值预填。
- 创建后操作：可勾选“创建后自动连接”，并设置连接并发（默认 8）。
- 视频设备不参与批量创建，提示单台联调。

### 4.3 批量操作

- 连接/断开按并发池执行（默认 8，避免瞬时压满主进程/服务端），显示进度与失败明细。
- 删除先断开连接、清理动态注册，再移除本地配置；失败设备保留并列出原因。
- 批量连接通过 `connectDevices`、`disconnectDevices`、`removeDevices` 统一实现（`src/utils/fleetOps.ts`）。

## 5. 压测中心设计

### 5.1 目标选择

- 多选设备（按协议分组、可搜索）；支持“选择在线设备/选择全部/清空”。
- 显示已选数量、在线/离线数量、协议标签。
- 视频/GB28181 不在可选协议列表内；从其他入口带入时自动过滤并提示。
- 可配置“开始前自动连接离线设备”，连接并发可调。

### 5.2 负载模型

- 模式：固定请求数 / 持续时长。
- 并发 Worker：1-500，每个 Worker 循环发送。
- 发送间隔：每个 Worker 每轮之间的等待（0 表示尽可能快）。
- 爬坡时间：Worker 启动按时间均匀铺开。
- 超时时间：单次发送超过该时间计为失败。
- 固定请求数模式按全局请求计数停止；时长模式按结束时间停止。

### 5.3 发送内容

- 上报类型：属性 / 事件（HTTP/MQTT/CoAP）。
- 数据模板：复用“数据模板”页维护的模板。
- 自定义 JSON：填写后覆盖模板，启动前校验 JSON。
- 协议专属参数（按已选协议显示）：
  - MQTT：Topic 模板，支持 `{productKey}`、`{deviceName}` 占位符。
  - WebSocket/TCP/UDP：消息模板，支持 `{deviceName}`、`{productKey}`、`{seq}`、`{timestamp}`。
  - LoRaWAN：FPort。
  - SNMP：OID 列表（通过 Connector GET）。
  - Modbus：功能码、起始地址、读取数量。

### 5.4 运行引擎

`src/utils/loadEngine.ts` 实现独立于 React 的 `LoadRunner`：

- Worker 池：并发数即 Worker 数；每个 Worker 按间隔循环，按全局序号从设备池轮询选取设备。
- 停止条件：固定请求数达到上限；或持续时间到达；或用户停止。
- 暂停：Worker 在发送前等待，暂停期间不产生新请求；继续后恢复。
- 超时：`withTimeout` 对 IPC Promise 计时，超时计失败（底层请求可能仍在执行，但不再阻塞 Worker）。
- 指标：
  - 计数：sent/success/failed/inFlight。
  - TPS：按 500ms 采样窗口计算。
  - 延迟：平均、P50/P90/P95/P99、最大；最多保留 2 万个样本。
  - 协议分布：每个协议的发送/成功/失败/平均延迟/P95。
  - 错误 Top：按错误文案聚合，最多展示 6 条。
  - 时间线：每秒采样 TPS 与失败数，用于 SVG 趋势图。
- 单实例节流：快照每 500ms 回调一次，避免每请求触发 React 重渲染。

### 5.5 结果

- KPI：已发送、成功、失败、TPS、成功率、进行中、耗时、平均/P50/P95/P99/最大延迟。
- 进度条：固定请求数按 sent/total；时长模式按 elapsed/duration。
- 协议分布表、错误 Top、TPS/失败趋势。
- 历史：本次会话最近 20 次，含设备数、请求、成功/失败、TPS、P95。
- 导出：完整 JSON 报告（配置、设备清单、最终快照、历史）。

## 6. 协议适配

| 协议 | 发送方式 | 前置条件 |
| --- | --- | --- |
| HTTP | `/api/v1/protocol/http/property/post` 或 `/event/post` | 设备已认证，token 有效 |
| MQTT | 向 Topic 发布 JSON | 设备 MQTT 客户端已连接 |
| CoAP | CoAP Bridge 属性/事件 | token 有效 |
| WebSocket | 复用 WS 连接发送文本 | 设备 WS 已连接 |
| TCP | 复用 TCP 连接发送按行消息 | 设备 TCP 已连接 |
| UDP | 复用 UDP 会话发送报文 | 设备 UDP 已初始化 |
| LoRaWAN | 模拟网络服务器 Webhook 上行 | Webhook 可达 |
| SNMP | Connector GET | Connector 可访问目标 |
| Modbus | Connector 读取保持/输入寄存器 | Connector 可访问目标 |

视频/GB28181 依赖摄像头、ffmpeg 与 SIP 会话，单机资源消耗大，不提供批量压测。

## 7. 布局与交互

- 取消固定 1760×960 缩放画布，改为 `100dvh` 流式布局：顶部导航 + 内容区滚动。
- 顶部导航固定四个页面，当前页写入 localStorage，重启后恢复。
- 设备详情使用 Drawer（最大 1280px / 96vw），不挤压主界面。
- 所有危险操作二次确认；批量失败使用弹窗列出设备与原因。
- 快捷键保留：`Ctrl/Cmd+N` 新建、`Ctrl/Cmd+Shift+C` 批量连接、`Ctrl/Cmd+Shift+D` 批量断开。

## 8. 持久化与大批量性能

- 设备配置和模板沿用 zustand persist + Electron store。
- 新增 200ms 合并写入，避免批量连接时每个状态变化都全量写盘。
- localStorage 仅保存 1MB 以内数据，大批量配置以 Electron store 为准，避免 5MB 配额错误。
- 批量创建一次写入（`addDevices`），不是逐台 `setState`。
- 压测指标只保留有界样本（2 万延迟、5 千/协议、60 个时间线点），避免长时间运行内存膨胀。

## 9. 取舍与限制

- 压测 Worker 数上限 500、设备创建上限 2000，是本机 IPC/连接资源的保守值；实际能力取决于机器、Connector 与网络。
- MQTT/WS/TCP 每台设备都是真实连接，1000 台以上需评估主进程内存与 Broker 连接上限。
- SNMP/Modbus 批量压测的压力主要落在 Connector 与目标设备，不是“模拟 1000 台独立设备”。
- 视频/GB28181 仍只支持单设备联调。
- 压测历史只保存在当前会话，不落盘；需要留存请导出 JSON 报告。
- 离开“压测中心”页面会停止当前压测（组件卸载时主动停止），避免后台无界面持续发压。
