# 前端交互友好性整改设计说明

> 模块: `firefly-web`
> 日期: 2026-11-15
> 状态: Done
> 范围: 控制台交互与用户友好性整改（不含手机验证码获取、不含移动端响应式）

## 1. 背景

对 `firefly-web` 全量页面做交互与用户友好性审查后，确认了一批会阻断操作、造成数据丢失或误导判断的问题：

- 分组页存在请求死循环；多步表单因 `preserve={false}` 丢失前几步字段。
- 定时任务抽屉与视频播放器存在编码损坏，用户看到 `????` 或乱码。
- 站内信通知渠道编辑必失败；协议解析、物模型编辑器关闭即丢失全部草稿。
- 全站大量 `catch` 静默失败、149 处写死“加载失败”、按钮无 loading、危险操作无确认。
- 手输数据库主键、手写 JSON、复杂表单用弹窗、页面夹杂设计理念文案等，偏离仓库前端规则。
- 认证层并发 401 各自刷新导致误登出，`/users/me` 一次抖动即清空会话。

本次整改以“不遗留”为目标，对上述问题逐项落地，并补充了公共交互能力，避免各页继续各自实现。

## 2. 目标与非目标

### 2.1 目标

- 阻断级问题全部消除：请求循环、数据丢失、乱码、必失败流程。
- 统一“进行中 / 失败 / 无数据 / 无匹配”四类状态表达，失败可见且可重试。
- 危险操作有后果说明与二次确认，提交有 loading 与防重。
- 枚举字段选择化、复杂表单抽屉化、长文本可复制、主键不外露。
- 页面文案只保留操作步骤、前置条件、结果影响、限制条件与失败处理。

### 2.2 非目标

- 不实现手机号登录的“获取验证码”（后端已有发送接口，但本期按业务要求不开放自助发送）。
- 不做移动端/窄屏适配（系统只在桌面端使用）。
- 不改后端接口、数据库结构与权限模型；后端能力缺口在页面用“禁用 + 说明 / 诚实标注 / 前置校验”处理，不伪造能力。

## 3. 总体方案

### 3.1 公共交互层（新增）

| 能力 | 位置 | 作用 |
| --- | --- | --- |
| 统一错误文案 | `src/utils/errors.ts` | `getErrorMessage(error, fallback)`：后端 message → 网络/超时/HTTP 状态 → Error.message → 兜底；替代原先 19 份重复实现 |
| 认证存储 | `src/utils/authStorage.ts` | 集中 token / 用户缓存 / 会话过期标记，避免请求层与 store 各写一套 key |
| 请求层 | `src/utils/request.ts` | 401 单飞刷新（并发请求共享一次 refresh）、刷新失败派发 `firefly:session-expired`、不再整页 `location.href` 跳转 |
| 渲染兜底 | `src/components/AppErrorBoundary.tsx` | 渲染异常显示可重试/可复制的错误页，避免白屏 |
| 全屏加载 | `src/components/FullPageLoading.tsx` | 会话引导阶段统一品牌加载态 |
| 长文本复制 | `src/components/CopyText.tsx` | 编码、密钥、报文、Trace、地址等一键复制，工具提示看全 |
| 列表空态 | `src/components/ListEmpty.tsx` | 区分“暂无数据”与“筛选无结果”，提供清空筛选 |
| 实体选择器 | `src/components/EntitySelect.tsx` | 用户/产品/设备/租户远程搜索，替代手输主键与 500 条盲区 |
| JSON 编辑器 | `src/components/JsonEditorField.tsx` | Monaco + 实时校验 + 格式化 + 模板插入，替代裸 TextArea |
| 未保存保护 | `src/hooks/useDirtyGuard.ts` | 路由级脏标记 + `beforeunload` + 关闭确认 |
| 可暂停轮询 | `src/hooks/useAutoRefresh.ts` | 可见性感知、防重叠、支持暂停与“最后刷新时间” |
| 页签激活 | `src/hooks/usePageActivation.ts` | keep-alive 页面切回时刷新，解决“回到页签看到旧数据” |
| 单行防重 | `src/hooks/usePendingAction.ts` | 表格行内动作防重复点击 |

### 3.2 布局与导航（`BasicLayout`）

- 侧栏折叠态、菜单展开分组持久化到 `localStorage`；切换路由时只合并当前路径所在分组，不再强制覆盖用户展开的其他分组。
- 页签持久化到 `sessionStorage`，刷新后恢复；单个页签可关闭，关闭有未保存修改的页签会二次确认；新增“关闭其他 / 关闭全部”。
- 页签改为单行横向滚动，避免多页签换行把内容区不断下推；最多保活 12 个页面，防止长时间使用后内存持续增长。
- 页签切回时派发 `firefly:page-activated`，列表页按需重新拉取数据；首次进入不重复请求。
- 菜单树加载失败显示错误与“重试”，不再静默渲染空侧栏；无菜单时显示明确空态。
- 折叠按钮、页签关闭、面包屑、账户菜单改为可聚焦的原生按钮并补 `aria-*`。
- 会话过期时保留回跳地址并提示“登录状态已过期”，不再静默踢回登录页。
- 账号信息刷新失败（非 401）时保留缓存会话，显示可重试横幅；权限接口失败不再把权限清空为“无权限”。
- 修改密码校验与后端约束对齐（6-64 位、新旧不同），补充强度建议。

### 3.3 页面级统一整改

1. **状态与反馈**：所有请求 `catch` 使用 `getErrorMessage` 并给出动作上下文；列表失败显示 `Alert + 重试`；提交/删除/启停按钮补 loading 与防重；行内动作使用 pending。
2. **危险操作**：删除、停用、注销、关闭告警、广播、重置密码、密钥停用等均写明影响对象、后果与可恢复性；一次性密钥弹窗禁止 Esc/遮罩关闭。
3. **表单**：枚举与实体字段改选择控件；多字段/多分区/JSON/联动的表单改抽屉；关闭时用脏检查拦截；切换产品/项目等会清空下游字段时先提示。
4. **列表**：筛选变化重置分页；空态区分筛选；长文本可复制或可看全；统计口径标注“全局 / 当前页”，不再用当前页数据冒充全局。
5. **主键收敛**：用户/设备/租户/产品/围栏等展示改用业务名称与业务键；无法解析时显示“未知 X”，不显示裸 `#id`。
6. **轮询**：实时会话、监控、任务中心、告警记录等改为可暂停 + 最后刷新时间；浏览器标签隐藏时暂停。
7. **文案**：删除设计理念、能力宣传、布局说明；保留操作约束（如“停止后不再投递”“关闭后不可再处理”）。

## 4. 关键设计取舍

### 4.1 错误提示不放在响应拦截器统一弹出

页面普遍已有带动作上下文的 `message.error`（如“保存设备失败”）。若拦截器再统一弹一次，会出现双提示且丢失上下文。因此拦截器只负责认证类副作用（401 刷新/会话过期），错误文案统一由 `getErrorMessage` 提取、由页面在正确位置展示。对确实静默失败的轮询（角标计数）保留静默但在面板内提供显式错误与重试。

### 4.2 认证刷新采用 single-flight

并发 401 共享同一个 refresh Promise；刷新失败才统一过期。`/users/me` 失败区分 401 与其他错误：401 清会话，网络/5xx 保留缓存会话并在布局提示重试。权限接口失败回退缓存权限，避免一次抖动导致整站“无菜单/无权限”。

### 4.3 keep-alive 保留，但增加激活刷新

关闭 keep-alive 会丢失用户正在填写的表单；保留 keep-alive 又会出现切回旧数据。最终方案是“保活 + 激活事件 + 页面按需刷新”，并把缓存上限设为 12，兼顾状态保持与内存占用。

### 4.4 脏检查采用路由级注册表

`useDirtyGuard` 把当前路由的脏状态写入模块级注册表，布局在关闭页签时读取同一份状态，页面自身关闭抽屉时用 `useConfirmDiscard`。这样刷新、关页签、关抽屉三个入口共享同一判断，不需要每个页面各自维护跨组件通信。

### 4.5 时间契约

后端部分查询 DTO（设备日志、审计日志、操作日志）使用 `LocalDateTime`，部分（设备数据、数据分析）使用字符串再交给数据库。前端分别提供：

- `toIsoDateTime`：用于字符串/时刻语义（数据分析、设备数据、有效期）。
- `toLocalDateTimeString`：用于 `LocalDateTime` 字段（设备日志、审计/操作日志），输出无偏移的 `YYYY-MM-DDTHH:mm:ss`。

保留响应层的时间字符串归一化用于展示；所有编辑提交均构造显式 payload，不把响应对象原样回传，避免展示格式写回后端。

### 4.6 后端能力缺口的处理方式

| 缺口 | 前端处理 |
| --- | --- |
| 手机验证码发送 | 本期不开放，登录页提示联系管理员或使用第三方登录 |
| 设备三元组导出不支持 groupId/excludeVideo | 按分组筛选时强制先勾选设备，避免超范围导出；payload 仍带字段便于后端后续支持 |
| 通知记录无重投、事件订阅无测试投递 | 不新增按钮，补充关键字检索、失败原因复制与错误态 |
| 数据查询只支持 limit | 界面明确“最近 N 条”，不伪装总页数 |
| SNMP v3 后端未实现 USM | v3 选项禁用并说明原因 |
| 审计/操作日志无业务对象编码 | 详情以可复制编号作为次要信息，主视角改为用户/模块/对象类型 |
| 共享策略事件权限/限流/有效期未执行 | 保留配置但页面不宣称已生效，交付说明记录 |

## 6. 风险与后续

- 本次未做浏览器 E2E；验证边界为 TypeScript、ESLint、生产构建与逐文件代码复核。建议联调时重点回归登录过期、页签关闭、长表单关闭确认、批量操作。
- 设备分组页曾存在请求循环，已改为 ref + 请求序号；联调时观察 `/device-groups/{id}/devices` 是否只请求一次。
- 多步表单（角色、用户、系统菜单）改为保留挂载；联调时按“第一步 → 下一步 → 保存”验证字段完整。
- 时间字段依赖后端类型：若后端改为 `Instant/OffsetDateTime`，前端应统一改回 `toIsoDateTime`。
- 仍存在 29 条 `react-hooks/exhaustive-deps` 警告（既有“渲染内 fetch + effect”模式），不影响构建；后续可逐步收敛，避免为消警告引入重复请求。
